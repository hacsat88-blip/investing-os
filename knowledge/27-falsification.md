# 27 反証エンジン v1

投資仮説は「支持する材料が増えたか」ではなく「撤回条件が成立したか」で管理する。theses.csv の `falsifier` を自由文のまま置くと、誰も検査しないまま保有だけが続く。ここでは撤回条件を機械可読にし、出典付きの観測値で毎回殴る。

## 撤回条件の書き方
`falsifier` 欄に、1行1条件で書く。セミコロン区切りも可。

- `@falsify <指標> <演算子> <値> [単位] : <ラベル>` — 条件が成立したら仮説に反する。
- `@stale <指標> <日数>d : <ラベル>` — 観測がこの日数より古ければ要注視。

演算子は lt / lte / gt / gte / eq / ne。例：

```
@falsify 営業利益率 lt 10 % : 利益率が二桁を割る
@falsify 売上成長率 lt 0 % : 成長の停止
@falsify 希薄化 gt 10 % : 1年で10%超の株式増加
@stale 営業CF 120d : 四半期開示を追えていない
```

`@` で始まらない行は自由文として保持し、検査対象にはしない。自由文しか無いカードは「仮説が正しい」ではなく `TEXT_ONLY`＝検証不能として扱う。

## 画面からの入力（選択式）
アプリの「① 投資仮説」カードでは、保有理由・期待する変化・反対仮説を分類から選び、その下の自由記述で具体を書く。保存される値は1行目が `#CODE ラベル`、2行目以降が自由記述である。分類を選ばず自由記述だけでもよい。選ばなかった分類を「該当なし」とは解釈しない。

撤回条件は、テンプレを選ぶ → 基準値を入れる → 「この条件を追加」で `@falsify` / `@stale` の行が生成される。生成後の行は自由に編集・削除できる。カード下部に「検証できる条件: N件」を表示し、0件なら反証エンジンが UNTESTABLE と報告することを明示する。

テンプレ定義は `app/catalog.py`（保有理由11・期待7・指標12・撤回条件14）にあり、`/api/state` の `catalog` で画面へ渡す。テンプレを増やす時は、生成される行が `parse_rules` で1件として読めることをテストで確認する。

## 判定
観測値は `falsify-input-v1` で渡す。1件ごとに holdingId、指標、値、基準日、出典ID、品質（FACT/EST/UNKNOWN）を持つ。出典IDの無い観測、基準日の読めない観測は無視する。同じ指標に複数あれば基準日が新しいものを採る。

- いずれかの撤回条件が成立：`CHALLENGED`。保有の前提を再検討する。
- 観測が無い、または古い条件が残る：`WATCH`。支持ではなく「確かめていない」である。
- 全条件がEST（推定）のみで不成立：`WATCH`。一次資料で再確認する。
- 全条件がFACTで不成立：`SUPPORTED`。
- 機械可読な条件が無い：`UNREVIEWED` のまま、`UNTESTABLE` と報告する。

`SUPPORTED` は「この撤回条件が今回は成立しなかった」以上の意味を持たない。条件の設計が甘ければ、支持は情報量ゼロである。条件は保有理由と一対一で書く。

## 運用
```
python3 app/falsify.py audit                        # 撤回条件が検証可能かの点検
python3 app/falsify.py template --output obs.json   # 必要な観測値の一覧
python3 app/falsify.py run --input obs.json --output proposal.json
```
`run` は theses の状態・最新値・確認日時・出典の更新案（PROPOSED）を作るだけで、CSVは書き換えない。ユーザーがアプリで差分を確認し保存して初めて台帳に入る。holdings、targets、decisions は変更しない。

`audit` の `TEXT_ONLY` と `EMPTY` は、その保有の撤回条件が検証できない状態を示す。これは調査課題（research.csv）に落とすべき欠落であり、放置した分だけ「なんとなく持っている」が増える。
